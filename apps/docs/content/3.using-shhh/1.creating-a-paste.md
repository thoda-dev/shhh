Paste your text, choose how long it should live, and get a link. That is the whole flow — no account
needed unless the instance says otherwise.

## Options

**Expires in** — days before the paste disappears. Leave it empty to use the instance default. The
instance caps how far ahead you can set it, and pastes always expire; there is no permanent option.

**Max reads** — how many times the paste may be decrypted before it is destroyed. Leave it empty for
the instance default, or switch to *unlimited*. The counter is decremented atomically, so a
one-read link cannot be read twice even under concurrent requests.

**Password protection** — adds a second key layer derived from your password with Argon2id. The
recipient needs both the link and the password.

::warning
A wrong password still consumes a read. The server never sees your password and cannot check it
before handing over the ciphertext — the failure only surfaces in the recipient's browser. Warn
whoever you send it to.
::

## Files

File uploads require an account. The file and its name are both encrypted in the browser; only the
MIME type is stored in clear, so the browser knows what to do with it on the way out.

The size cap is set by the instance — 2 MB by default.

## Sharing the link

The link contains the decryption key after the `#`. **Copy it whole.** Truncating it at the `#`
gives a link that finds the paste but cannot decrypt it.

Treat the link as the secret itself: anyone holding it can read the paste.

::note
Two share buttons appear once your paste is created.

**Share by email** opens your own mail client with the link pre-filled and no recipient — nothing
goes through the server. Available to everyone.

**Also send the link by email**, offered at creation for signed-in users, has the server send one
message with all recipients in blind copy. It is the only moment the key reaches the server; see the
[security model](/self-hosting/security).
::

## Reading a paste

Opening a link shows the paste's metadata first — whether it exists, whether a password is needed,
how many reads are left. **Nothing is decrypted and no read is consumed** until you click *Reveal*.

That two-step flow is what stops chat unfurlers and antivirus scanners from burning a one-read link
before its recipient ever clicks.
